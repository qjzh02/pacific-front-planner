# 太平洋战线阵容规划器

《战舰世界》太平洋战线小游戏的本地辅助工具。填写敌军、可用卡牌、生命和道具库存，计算各组从左到右的阵容与装备，并规划后续波次的剩余资源。

本项目由玩家独立维护，与游戏官方无隶属关系。工具只做计算和用户主动发起的页面读取，不自动登录、部署阵容或执行战斗。

## 能做什么

- 支持1至6波，每波4、8、12、16或20个敌人，每4个敌人独立成组。
- 收录30张卡牌、60个方向效果和11种道具，其中9种参与配队。
- 计算生命、相邻友军增益、敌军弱点、方向减益和装备效果。
- 每组独立设置属性下降、增益／减益失效、效果减少50%、禁用道具和舰种限制。
- 同一张卡牌每波最多使用一次，生命和道具余量延续到下一波。
- 显示双方结算战力、效果来源、搜索模式和每波后的资源余量。
- 自动保存当前浏览器输入；支持暂停、恢复、后台暂停、取消和可选计算预算。
- 手动切换游戏据点后自动定位阶段和组，也可选择目标组或导入 HTML／TXT；支持保留资源的行动重置与撤销。

## 快速开始

安装 **Node.js 24或更新版本**，从 GitHub 下载仓库 ZIP 并解压，或克隆仓库。打开项目目录中的终端，运行：

```sh
node server.mjs
```

然后在浏览器打开 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。服务启动后请保持终端打开，按 `Ctrl+C` 可停止服务。

Windows 也可以在项目目录的 PowerShell 中运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

日常使用只需要 Node.js 和现代浏览器，**无需 `npm install`，无需 Python**。Python 仅用于修改数据后重建数据库。

不要直接双击 `index.html`，页面需要本地服务加载数据和后台计算。服务仅监听本机 `127.0.0.1:8765`；如果提示端口被占用，请先检查是否已经启动了一个实例。

## 如何规划一场行动

1. 设置波次和每波敌军数量，一个据点对应一组四个敌人。
2. 录入每个敌人的战力和最多两种弱点，并设置对应组的战场条件。
3. 勾选自己拥有的卡牌，填写行动开始时各卡的生命。
4. 填写实际道具库存。公开版初始库存全部为0，不代表玩家拥有的数量。
5. 点击“开始计算”，按结果安排各波各组的阵位和装备。

“载入示例”可以快速体验功能，但会覆盖当前输入。示例的敌军和道具数量是演示数据。计算只模拟生命和库存消耗，不扣减输入，也不操作游戏。

输入保存在当前浏览器的本地存储中，刷新会恢复。同名卡牌当前只代表一个单位，不支持同名多张同时部署。更换浏览器、清除站点数据或使用不同地址打开页面，保存的数据不会自动迁移。

## 计算时间与暂停

默认不限计算时间，并在页面切到后台时暂停。也可以手动暂停和继续；恢复会从当前搜索进度继续，取消或修改输入会终止当前计算。设置和旧输入兼容，旧输入默认不限时、启用后台暂停。

可在“计算规则与搜索设置”选择30秒或60秒预算。预算累计搜索执行时间，排除暂停和调度等待。达到预算时保留已找到的阵容并结算资源，不再开始新的重试；当前未完成组标为“搜索未完成”，后续空组标为“尚未搜索”。页面和复制方案都会提示预算已用尽，不能把部分穷举视为已穷举，也不能把未搜索当成没有可赢阵容。打断重试时仍只接受整场胜场增加的方案。

同一次行动中，敌军、条件、卡牌生命、库存、模型及搜索设置完全相同时可复用搜索结果，页面会明确说明复用；实际搜索分支数不重复计入。缓存不持久化，也不跨计算调用复用。

## 从游戏页读取敌军

采集支持亚洲服太平洋战线页面。卡牌、生命和库存仍需手动填写，默认按来源自动新增阶段与组，无需预设数量。

1. 新行动可先点击“重置行动”，回到一波一组4个空敌军。卡牌选择、当前生命、库存及计算设置均保留，不自动回血；可点击“撤销重置”恢复敌军和条件。
2. 在“首次连接与离线导入”中复制采集脚本，在同一浏览器的游戏据点配队页控制台粘贴并运行。
3. 点击游戏页右下角“连接／打开本地求解器”。浏览器可能询问本地网络访问权限，由玩家自行处理。
4. 从阶段1据点1按顺序手动打开据点，点击“抓取当前据点”或导入 HTML／TXT。默认按阶段和累计据点编号填入，重复采集更新原位置。

据点号是整场累计编号，各阶段可能有不同组数。已有来源用于确定阶段起点，新阶段从前阶段末点后开始；不能将据点号直接减1，也不固定按每阶段5组取模。缺少边界、来源错位、重复据点或混用行动时会提示按顺序采集或切换手动填入。最多仍为6波、每波5组。关闭“按阶段和据点自动填入”后，可手动选择目标组，成功后选中下一组；旧输入默认开启自动填入。

采集仅替换本组敌军和支持的区域条件，扩容保留其他组与资源。支持刷新后撤销最近一次采集或重置；自动新增且未再修改的尾部组／阶段随撤销移除，其他原有组及资源的后续修改保留。目标组或新增区域已有手动修改时拒绝覆盖。重置会终止计算、取消待处理采集，迟到结果不能写回；新采集替换旧撤销记录，只保留最近一次操作。

游戏整页刷新或本地服务重启后，需要重新复制脚本并配对。导入 HTML／TXT 仅在惰性模板内解析，不执行样本脚本。采集通过本机接口传送敌军和区域条件，保留来源、配对码及请求编号校验，不自动操作游戏。

采集采用**全胜规划时忽略“带入”、“指定”和“全域”**的简化前提。“全域”作为下一关带入，不从当前显示战力中扣除其提升；手动条件仍参与计算。如果方案未全胜，应重新核对游戏中的实际带入条件。

当前支持区域三项属性下降、敌方战力提升、禁用单位类型、禁用变项、四种效果开关和无条件。区域增益／减益−50%设置对应削弱开关，−100%设置对应失效开关；每次完整复制四个开关，支持不同类别混合，拒绝同类重复、其他比例和未知内容。道具直接增加的属性及“无视战斗条件”规则沿用既有模型；这不构成新的取整校准。

区域禁用类型从专用栏目识别并转换为允许类型的补集，不按库存卡牌状态猜测。仅支持我方原有飞机、战列舰、巡洋舰、驱逐舰；未知、缺失、重复图标或全部禁用会拒绝导入。区域“禁用变项”禁止本组灰色与绿色装备，不停用卡牌本身的效果、不修改库存。带入、指定和全域中的这些限制仍忽略。

敌军类型支持飞机、战列舰、巡洋舰、驱逐舰、潜艇、岸防炮和水雷。后三种仅加入敌军识别、增益匹配与中文来源展示，不扩展我方可选卡牌或区域允许类型。未知图标和名称不一致仍拒绝导入。

敌方全体与舰种、带入与区域的明确比例统一按幅度加算，不再使用比例或层数白名单。支持同栏多行、多个分栏、多个全体栏目和三层以上组合；同舰种有效行合并为一条合计比例来源，接口拒绝未合并的重复来源条目。比例必须是有限非负数，舰种提升条目须为正数；带入失效行不计入合计，指定与全域继续忽略。

存在带入时，先按每位敌军匹配的全部带入及区域比例恢复整数原战力，复算须能重现显示值，再仅保留区域提升：

```text
原战力 = round(游戏显示战力 / (1 + 带入比例合计 + 区域比例合计))
导入战力 = round(原战力 * (1 + 区域比例合计))
```

受带入提升的敌军须有加成标记。没有带入时保留已提升的显示战力；每位敌军的 `powerIncrease` 保存区域全体比例加匹配舰种比例，供求解器按原战力结算减益，避免重复加成。来源同时记录去除的带入及保留的区域比例。手动修改已采集显示战力仍保留比例并重新校验可还原性。

已有实测覆盖单独全体8%、全体8%与舰种16%的加算及部分区域16%组合。本次补充全体16%带入：145／152／165／142→168／176／191／165，符合 `round(base * 1.16)`，导入恢复原值并保留区域舰种限制。匿名记录位于 `sources/enemy-carried-global-16.json`。同舰种双16%合并为32%的人工样本235／277／204／202按既有规则还原为178／210／204／202；它未提供独立原战力，不能称为新的取整实测。

其他明确比例与多层组合采用已确认加算公式及现有整数显示取整进行**模型外推**，单独记录于 `rule_sources.model_assumptions.general_enemy_capture`，不扩展我方属性或战斗减益取整的实测范围。未知内容、缺失比例、非数值／负数／非有限值、已受我方减益的敌军及不能复算的战力会拒绝导入，保留原输入。

状态检查在未连接时每5秒、连接空闲时每2秒、后台时每20秒进行，等待实时抓取时每250毫秒检查；恢复可见立即检查。游戏页仅收到抓取请求时解析DOM，可见／隐藏时分别约1.5／3秒发送心跳，保留90秒有效期及窗口隔离兼容。

更新后请重启本地服务、刷新规划器并重新复制脚本配对。只刷新网页不会更新运行中服务的校验。舰种来源必须含每位敌军的区域比例；旧全体来源可回退来源比例并校验，缺失或无效快照不会覆盖输入。

## 怎样理解计算结果

每组依次优先：胜出对位数更多、绿色道具更少、灰色道具更少、上阵单位更少、卡牌满血最低战力总和更低，最后才比较战力余量。同等胜场允许用两件灰色代替一件绿色；不会为了省道具主动降低本组胜场。

单组候选组合上限不超过200万时穷举，超过时使用有限宽度搜索。页面提供300、900、2400三种宽度，结果会标明搜索模式。

整场先按波和组的顺序规划。后续波次失败时，最多尝试12次在先前波次提前回血，只接受能提高整场胜场的方案，不替换已有绿色道具。

若仍有失败后组，再最多尝试4次为该组优先分配本波单位和装备，固定此前波次阵容，重算该波及后续波次，只接受整场胜场增加的方案。结果记录 `groupRepairs`，条件、输出组号和执行顺序仍保持原顺序，同波不重复用卡，生命与库存重新结算。如果已实际完成先前组，采用重排方案前需重新核对执行状态。

这些重试不枚举所有组间分配和跨波用卡，**即使某一组是穷举，整场仍不保证全局最优**；有限搜索也可能漏掉全胜阵容。

### 已使用的规则

- 生命3／2／1格时，属性倍率为1／0.9／0.8；上阵后扣1格生命。
- 回血先恢复2格，上限3格，再扣战后生命。
- 普通增益提高目标的一项属性30%，匹配弱点的减益降低敌军总战力20%。
- 同属性的道具和友军正向增幅加算；敌方增益与各次减益均在原战力上按幅度加算，两次普通减益为×0.6，普通与强化减益合计为×0.4。
- 方向按界面从左到右，效果仅在本组内生效，越界没有目标。
- 每单位最多装备一个灰色道具和一个绿色道具，装备受库存约束。
- 本组禁用道具时直接计算拒绝装备，穷举和有限搜索只考虑无装备，提前回血跳过该组；旧输入缺少 `itemsDisabled` 时默认关闭。
- “无视战斗条件”抵消装备者的属性下降，恢复其在增益失效时发出的增益，并抵消它发出的增益／减益减少50%。仅给接收者装备不会恢复其他单位发出的增益。

### 仍需实测校准

默认使用严格大于计胜、我方向下／敌方向上取整、属性下降单独乘算、零生命不可复活。默认公式为：

```text
我方最低战力 = Σ[基础属性 × 生命倍率 × (1 − 属性下降) × (1 + 正向增幅合计)] − 10
敌方战力 = 原战力 × (1 + 敌方增益比例 − 命中减益幅度合计)
```

相等胜负、取整阶段、属性下降与增幅的结算顺序、总属性+40%与其他增幅的组合、双友军增益的独立叠加实测及零生命回血仍需校准，可在“计算规则与搜索设置”调整部分模型选项。“无视战斗条件”是否绕过减益失效和舰种限制尚未确认，当前不实现。结果中的“胜出”表示按当前模型计算获胜。

敌方＋16%与一次普通20%减益已实测为 `round(原战力 × (1 + 0.16 − 0.2))`。其他增减益组合的加算公式已确认，取整尚待核对，沿用所选取整设置并在结果标注。敌军无减益时仍使用原始输入的显示值。

## 数据和隐私

页面读取 `data/cards.json` 和 `data/items.json`。SQLite 与两份核对表由相同 JSON 生成，不直接编辑。静态服务只允许访问指定前端文件；采集接口校验游戏来源、本次服务配对码和请求数据。

公开版不包含原始游戏页面、截图、浏览器输入备份、运行日志、上传截图文件标识或个人库存。`sources/` 保留文字整理记录，`html/` 和 `fixtures/` 为人工测试样本；JSON中的 `user_confirmed` 表示规则来源类别，不包含确认者身份。它们不能替代原始截图证据。

手动规划无需连接游戏。启用采集时，脚本将当前据点的敌军和区域条件发送给本机服务；项目没有云端上传、统计或遥测功能。本机采集服务只在内存中保留连接及最近结果，浏览器保存的数据仍由玩家自己的浏览器管理。

## 开发和验证

修改 JSON 后，在项目目录运行 Python 3：

```sh
python build_database.py
python test_database.py
python test_release.py
```

生成器会重建 `data/cards.sqlite3`、`CARD_CATALOG.md` 和 `ITEM_CATALOG.md`，不要使用 `python -O`。公开版道具默认数量维持0；具体行动库存应在网页中输入。

计算及本机接口测试不需要额外依赖：

```sh
node --test --test-isolation=none solver.test.mjs capture-relay.test.mjs capture-layout.test.mjs action-regression.test.mjs
```

测试命令使用 [Node.js 的测试隔离选项](https://nodejs.org/api/cli.html#--test-isolationmode)，请使用上述版本的运行时。

可选浏览器测试使用 Playwright。已有环境可直接复用；没有时可以单独安装测试依赖：

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node --test --test-isolation=none capture.test.mjs
```

如果使用本机已有浏览器，可在 PowerShell 中用 `CAPTURE_BROWSER` 指定可执行文件：

```powershell
$env:CAPTURE_BROWSER = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
node --test --test-isolation=none capture.test.mjs
```

浏览器测试通过隔离的测试页面和模拟游戏样本运行，不需要真实账号或正在运行的规划器服务。公开版初始库存与文件检查由 `test_release.py` 验证；自动检查不能识别所有形式的个人信息，新增文件仍需人工核对。

| 文件 | 用途 |
|---|---|
| `solver.js`、`worker.js` | 战力计算、阵容搜索及后台执行 |
| `app.js`、`index.html`、`styles.css` | 输入、保存和结果界面 |
| `game-capture.js`、`capture-relay.mjs` | 只读采集及本机通信 |
| `data/`、`sources/` | 可编辑数据、生成数据库和公开文字记录 |
| `build_database.py`、`schema.sql` | 数据校验和数据库构建 |
| `*.test.mjs`、`test_*.py`、`html/`、`fixtures/`、`test-fixtures/` | 自动验证及人工样本 |
| `server.mjs`、`start.ps1` | 本地服务和Windows启动入口 |
